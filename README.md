# 合同管理系统 - 本地开发与打包指南

本项目是一个基于 Next.js、Firebase 和 Genkit 的合同管理系统，并已配置 Electron 支持以生成 Windows EXE 文件。

## 1. 系统核心功能概览

### A. 智慧经费执行看板
* **科技感圆环**：采用鲜亮霓虹色系，弧形区域平均等分，各渠道名称直接显示在色块内部。
* **智能自动归档**：当经费渠道下所有合同 100% 支付完成后，该渠道自动从看板退出，圆环自适应重算剩余比例。
* **全局进度追踪**：中心动态显示全局资金执行率，点击色块可下钻查看详细财务指标。

### B. 精细化财务管理
* **三级金额逻辑**：管理 `合同价`、`补充协议`、`最终结算审定价`。系统根据审定价（若有）或合同总额自动锁定待付余额。
* **智能支付试算**：支持按 80%、95%、97% 或尾款比例进行快速金额试算并一键录入。
* **琥珀色财务备注**：独立的财务特别备注区，支持记录罚款、扣项、政策性调减等特殊财务状况。

### C. 全周期考勤电子档案
* **项目级独立管理**：支持“项目-合同细项-人员”三级联动，为每个标段建立独立的管理小组。
* **智能随机生成**：内置算法精准控制岗位天数（高管层每周休2天，执行层每周休1天），并实现全团队错峰休息。
* **精确周期控制**：严格根据开竣工日期控制有效考勤日，非周期内天数自动锁定并置灰。
* **批量跨月导出**：导出符合财务审计规范的 Excel 报表，固定 35 行高，按月份自动分 Sheet 存储，底部自带签字栏。

## 2. 考勤管理模块使用指南

为了确保考勤数据的合规性与真实感，请遵循以下流程进行操作：

### 第一步：设定考勤统计周期
在考勤页面顶部的日期选择器中，设置该工程的“**考勤开工日期**”和“**考勤竣工日期**”。系统将自动计算覆盖的所有自然月，并生成逐月核对菜单。

### 第二步：切换管理视角
1.  使用“**项目视角**”下拉框选择您要管理的项目。
2.  （可选）使用“**合同细项**”下拉框进一步精细化管理特定标段。
3.  页面表格和人员名单将仅显示当前视角下的数据，确保“选哪个标段，管哪个小组”。

### 第三步：管理人员录入
1.  在表单中录入姓名与职务。
2.  **职务识别**：系统会自动识别“项目经理”、“技术负责人”和“总监”等职务以应用更优厚的周休规则。
3.  点击“+”号添加，人员信息将永久关联至该项目及其合同细项，数据互不干扰。

### 第四步：一键智能填充
点击“**填充全周期考勤**”按钮，系统将执行以下高级算法：
*   **差异化周休**：项目经理/技术负责人/总监每周休息2天（出勤约21-22天）；其他人员每周休息1天（出勤约26-27天）。
*   **全局错峰**：自动计算全团队每日负载，确保每天都有人员在岗，严禁全员集体休息。
*   **防连休约束**：单人连续休息天数**严禁超过2天**，确保出勤的连续性。
*   **区间锁定**：严格在开竣工范围内生成，范围外的格子自动标记为“X”不计入统计。

### 第五步：报表预览与导出
1.  在表格中查看各月份的考勤流水（出勤标记为“√”）。
2.  点击“**导出全周期报表**”：系统将生成一份 Excel，每个月自动分配一个 Sheet 标签。
3.  **打印存档**：报表格式对齐审计标准（35行高、蓝白表头），底部已为您预留“项目负责人”与“统计人”手写签字区。

## 3. 环境准备
* 安装 [Node.js](https://nodejs.org/) (推荐 v18+)
* 拥有一个 Firebase 项目（当前代码已内置 Firebase 配置）

## 4. 本地安装与启动
1. **下载并解压**：从 Firebase Studio 下载项目源码并解压。
2. **安装依赖**：
   ```bash
   npm install
   ```
3. **本地预览 (Web)**：
   ```bash
   npm run dev
   ```
   访问 [http://localhost:9002](http://localhost:9002)

## 5. 打包成 EXE 文件 (Windows)
我们使用 Electron 和 `electron-builder` 进行打包：

1. **构建 Next.js 生产环境**：
   ```bash
   npm run build
   ```
2. **打包生成 EXE**：
   ```bash
   npm run electron:build
   ```
3. **获取安装包**：打包完成后，进入项目根目录下的 `dist-electron` 文件夹，即可找到生成的 `.exe` 安装程序。

## 6. PWA 网页版（可安装到桌面/手机）

系统已支持 PWA，无需 Electron 也能像本地软件一样使用：

* **电脑端（Chrome / Edge）**：访问网址后，点击地址栏右侧的"安装"图标，或菜单 →"安装合同管理系统"。安装后会生成独立窗口和桌面图标。
* **手机端**：浏览器菜单 →"添加到主屏幕"，即可全屏独立运行。
* **离线能力**：Service Worker 会缓存界面与静态资源，断网时仍可打开应用查看已加载的界面；合同数据本身仍依赖 Firebase 云端同步，首次加载后 Firestore 的本地缓存也支持离线读写、联网后自动补传。
* **版本更新**：发布新版本后，应用左下角会出现"发现新版本"提示，点击"立即更新"即可切换。
* 相关文件：`public/manifest.webmanifest`（应用清单）、`public/sw.js`（离线缓存）、`public/icons/`（图标，可运行 `node tools/generate-pwa-icons.mjs` 重新生成）。

## 7. 微信小程序版本（`weapp/` 目录）

`weapp/` 是独立的微信小程序工程（微信原生 + 云开发），与网页版共用业务规则但代码独立：

* 四个页面：合同明细、执行看板、结算归档、考勤管理（`pages/` 下）。
* 数据层 `utils/db.js` 完整复刻了网页版的计算规则（基准金额、执行率、80/95/97% 试算、错峰考勤算法）。
* 云函数 `cloudfunctions/exportExcel` 负责生成 Excel 并上传云存储，`getOpenId` 负责获取用户身份。
* 数据库结构与迁移步骤见 `weapp/docs/DATABASE.md`；Firestore 历史数据可用 `node tools/firestore-to-cloudbase.mjs <导出文件.json> [openid]` 转成云开发导入格式。

> 注意：小程序端无法复用 React 组件（无 DOM 环境），图表暂以进度条替代；如需经费圆环，后续可引入 ec-canvas。

## 8. 部署网页版到 Firebase Hosting（任何人可访问的网页软件）

网页版是纯静态导出（`output: 'export'`），数据存在 Firebase 云端，与托管平台无关。已配好 `firebase.json`（托管目录 `out/`）+ `.firebaserc`（项目 `studio-8690267022-4c1b6`）。

```bash
# 1. 安装并登录 Firebase CLI（仅需一次）
npm install -g firebase-tools
firebase login

# 2. 本地构建静态产物（生成 out/ 目录）
npm run build

# 3. 一键部署
firebase deploy
```

部署完成后会得到一个 `https://studio-8690267022-4c1b6.web.app` 形式的网址，任何浏览器/手机打开即可使用，登录后数据从 Firebase 云端实时同步。若要重新部署，重复第 2、3 步即可。

> 其他静态托管（Vercel / Netlify / 任意静态空间）也适用：直接把 `out/` 目录作为站点根目录上传，并把所有未匹配路径重写到 `index.html` 即可。
